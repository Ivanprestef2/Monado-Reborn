# Evidence: NVIDIA Reflex, runtime support (2026-11-18)

> Spanish version: [`reflex_2026-11-18.md`](reflex_2026-11-18.md)

**Question:** can NVIDIA Reflex (low latency) be integrated into Monado-Reborn?
**Result:** the Streamline + Vulkan path works end-to-end on the available machine (driver extension, feature,
markers, *sleep* and reports). Game integration and measuring the real gain are still pending. This is research:
no product code was changed. Design and plan in [`../reflex_research.md`](../reflex_research.md).

## Machine and build

- Windows 10.0.19044; **NVIDIA GeForce GTX 1050 Ti** (Pascal, no RTX), driver **582.78**, Vulkan **1.4.312**,
  a single Vulkan adapter.
- Streamline **2.14.16** production from `sdk/sl/bin/x64` (not in git). On load, Streamline verified the NVIDIA
  signatures of `sl.common.dll`, `sl.pcl.dll`, `sl.reflex.dll` and `NvLowLatencyVk.dll`.
- Tool: `tools/reflex_probe.cpp`, built with `zig c++` (exact command in the file header). It is not part of CMake
  or CI; it opens a hidden window and writes no files.
- Run: 2026-11-18 18:08 (UTC+3).

## Method

1. Direct Vulkan enumeration from the driver (throwaway probe): device and instance extensions.
2. `slInit` in *manual hooking* mode with `kFeatureReflex` + `kFeaturePCL`; the device extension comes from
   `slGetFeatureRequirements(kFeatureReflex)`, never hard-coded.
3. Vulkan device, surface and swapchain created in the same order as `runtime/nvn/vulkan/device.c`: instance →
   device → `slSetVulkanInfo` → Streamline proxy surface → proxy swapchain.
4. 240 frames with its own token, `eSimulationStart/End`, `eRenderSubmitStart/End`, `ePresentStart/End` markers
   and `slReflexSleep` before simulating.
5. Second run with `PROBE_DLSS=1`: DLSS requested too (unsupported on this GPU) to check that Reflex does not
   fall over with it.

## Results

| Check | Result |
|---|---|
| Driver extensions | `VK_NV_low_latency`, `VK_NV_low_latency2`, `VK_KHR_present_id`, `VK_KHR_present_wait`, `VK_KHR_timeline_semaphore` present |
| Reflex requirements | 1 device extension (`VK_NV_low_latency`), 0 queues, 0 features12/13 |
| `slIsFeatureSupported(kFeatureReflex)` | `eOk` (0) |
| `slReflexGetState` | `lowLatencyAvailable = 1`, `latencyReportAvailable = 1`, flash driver-controlled |
| `slReflexSetOptions(eLowLatency)` | `eOk` |
| 240 frames of markers + *sleep* | 0 sleep errors, 0 marker errors; mean sleep 0.038 ms (max 0.18 ms) in the first run, 0.083 ms in the second (one isolated 10 ms spike) |
| Per-frame reports | `gpuFrameTimeUs` ≈ 6900 us and valid timestamps |
| DLSS also requested (non-RTX GPU) | Reflex remains available; markers and reports still work |
| `slInit` cost | 1163 ms with Reflex + PCL, 1296 ms with DLSS also requested (it loads every SDK DLL it finds in the directory) |

## Limits

- **Real latency / gain was not measured.** The probe window is hidden and its FIFO swapchain is not synced to a
  monitor, so the *sleep* lasts 0.04 ms. That proves the API path, not an improvement. The gain depends on
  V-Sync/VRR/GPU load and is measured with the Reflex verification HUD and FrameView.
- One adapter (GTX 1050 Ti). Not tested on RTX, AMD/Intel or hybrid laptops.
- At probe time `sl.reflex.dll` and `sl.pcl.dll` were not deployed yet; T272 added them to
  `tools/install_dlss.py` and the copy scripts, so the current game can load the feature when enabled.
- The NVIDIA binaries and licenses are not in git (`sdk/` and `build/` ignored).
